## 先说清楚是哪一种转播

本文的「直播转播」是把 YouTube / Twitch / Niconico 的直播转推到 B 站直播间。多机录制 Fleet 里节点与控制面之间的 relay 通道是另一套机制，两者不要混用。

需要 B 站直播间已经开通直播权限。转播不代替录制，录制、遮挡与合并见[录制分段、画面遮挡与本地合并](@/docs/tutorials/recording-and-masking.md)。

## 能做什么

- **无人值守**：按「检测间隔」轮询外部平台，主播开播后自动在 B 站开播、下播后自动停播，不需要人守着。
- **取流与推流**：YouTube 用 `yt-dlp`，Twitch 与 Niconico 用 `streamlink`，再由 `ffmpeg` 推流。
- **时移缓存与裁剪**：可以先缓存 1–60 秒再推（用一点延迟换稳定），也可以裁掉不需要的画面区域。
- **弹幕与风控**：弹幕指令可以控制开播 / 停播；命中违禁词的直播会被停播，直播间封禁期间不会反复尝试开播。
- **配置与备份**：配置、Cookie 与监控数据存在加密 SQLite 里，可以导出加密备份；恢复只允许在空数据目录上做。
- **统计与日志**：`/relay/analytics` 看场次、时长、可靠性与开播日历，`/relay/logs` 看实时日志。

## 六个页面

| 页面 | 用途 |
| --- | --- |
| `/relay` | 转播总览：实时直播状态、优先频道、推流指标、Holodex 预告与主播列表；状态卡片上有开播 / 停播 / 重启 |
| `/relay/setup` | 首次配置向导：B 站账号（扫码登录与房间号）→ 基础参数（检测间隔与密钥）→ 频道与分区 |
| `/relay/manage` | 频道管理、分区管理、画面裁剪与时移缓存 |
| `/relay/settings` | 基础设置、平台与代理、密钥池与 Cookie、账号与会话、风控与过滤、存储与备份 |
| `/relay/analytics` | 推流统计与开播日历 |
| `/relay/logs` | 实时日志 |

首次配置还没完成时，只读接口返回 `412`、业务码 `not_configured`，页面据此提示去向导，而不是报错。

## 首次配置向导

1. 打开 `/relay/setup`，第一步用 B 站客户端扫码登录；房间号可以从账号自动读取，也可以手填后继续。
2. 第二步填检测间隔与推流密钥等基础参数。
3. 第三步选要监控的平台频道与初始分区名单，保存后就能在 `/relay` 开播。
4. 之后在 `/relay/settings` 按需配置代理、密钥池、风控与过滤。

`/relay/setup` 与 `/relay/settings` 需要 `relay.config`，也就是只有超级管理员能改。

## 从旧版 bilistream 恢复加密备份

恢复是整库覆盖，只允许在**空数据目录**上做，所以要在首次配置之前完成：

1. 全新安装并启动 WebUI，先不要跑完 `/relay/setup`。
2. 进 `/relay/settings` →「存储与备份」→「恢复备份」，选择旧实例导出的 `biliup.backup`，输入导出时设置的口令（至少 12 位，文件不超过 32MiB）。
3. 恢复成功后页面会提示并刷新配置，接着去 `/relay` 确认频道、分区与登录态都在。

已经写过配置的实例不允许再恢复，避免误覆盖生产数据；要迁移就先把备份导出来。

## 运行依赖

| 依赖 | 用途 | 备注 |
| --- | --- | --- |
| `ffmpeg` | 转推、时移缓存、抓帧 | 必须在 `PATH` 中 |
| `yt-dlp` | 抓 YouTube 流 | 新版需要 JS 运行时才能完整解析格式 |
| `streamlink` | 抓 Twitch / Niconico 流 | |
| `deno` | 给 `yt-dlp` 当 JS 运行时 | 官方 Docker 镜像内置 2.9.8 |

官方 Docker 镜像已经装好这四个。自己部署时把它们放进 `PATH`，缺哪个都会在取流时报错。

## 权限点

| 权限点 | 作用 | 超级管理员 | 操作员 | 只读观察者 |
| --- | --- | --- | --- | --- |
| `relay.view` | 查看转播页面与只读接口 | ✅ | ✅ | ✅ |
| `relay.control` | 开播、停播、重启等控制 | ✅ | ✅ | ❌ |
| `relay.config` | 修改转播配置，含向导与设置页 | ✅ | ❌ | ❌ |
| `relay.cluster` | 管理转播集群 | ✅ | ❌ | ❌ |

## 数据存储位置

- `data/relay/relay.db`：加密 SQLite，存配置、Cookie 与监控数据；导出与恢复备份都是整库操作。
- `data/relay/history.sqlite`：推流统计（场次、时长、可靠性），`/relay/analytics` 读的就是它。

首次配置没跑过时这两个文件还不存在，接口返回 `412`（未配置）；出现 `500` 说明是真正的内部故障，去 `/relay/logs` 看日志。
